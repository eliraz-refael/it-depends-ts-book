## Must fix

1. **Bonus 1's Principle spoils its Turn and reads as a checklist.** 05-bonus/01:7: "If two implementations pass but disagree on behavior you need, decide which one you mean and put the difference in the examples before the next attempt." That is the Turn at 239–302. The Principle runs two paragraphs and 11 sentences, and it doesn't sound like Eli. Proposed: **Prof. Eli Typeworth**: "Before asking for code, state what it must do in a form something can check: the signature, the project configuration, examples that should succeed and examples that should fail. A sentence in the request is an intention. Only what the checks express is a requirement; the rest is still ours to decide."

2. **Bonus 3's Principle lists the whole chapter.** 05-bonus/03:5: "A caller edited in the patch cannot speak for the unedited callers elsewhere. Put it back and find why it needed changing… Even when the contracts agree, runtime tests still have to check the values and effects." These are the Debate (154, restoring badge.ts) and the Verdict exchange (406–408). It is also the same rule as Ch24's, which says "If we edit the caller too, we have another change to justify". Proposed, in Daniel's dry voice and setting up Oded's "No *written* public API changes" at 221: **Daniel Compiler**: "When a patch says it changes no public API, believe the declarations, not the summary. Emit them before and after and read the difference. Inferred types are published too: a body can change a contract without anyone typing a word of it."

3. **Daniel's four Principles, compared directly.** Ch20 (07-currying:5) is distinct: a definition and a judgment ("Judge a staged API by what each call establishes"). Ch24 and Bonus 3 make the same claim in the same first-person procedural form ("I keep that caller in the test…" / "I review an API-preserving patch…"). Ch24, Ch27 and Bonus 3 all lean on "same compiler and settings" (Ch24:5 "under its settings"; Ch27:5 "same compiler and options"; B3:5 "same compiler and settings"). None of the three late ones has the dry humor from his bio. Ch27 and Bonus 2 also end the same way: "A faster check of a different contract can be useful, but then…" (Ch27:5) and "Generating a more accurate description is useful, but it doesn't…" (B2:5). Fix with item 2 plus the following:
   - Ch24:5 → "A conversion that claims to keep a contract has to keep it for the callers nobody edited. The compiler can only vouch for the files you handed it."
   - Ch27:5 → "If a type change is meant to make checking cheaper, measure it the dull way: same workload, same compiler, one change per run. Then the result has to say two things: what got cheaper, and what callers can still rely on." This drops the emit-comparison and runtime-validator steps that Gil and Daniel perform at 99–107, and drops "two decisions", which is the Verdict.

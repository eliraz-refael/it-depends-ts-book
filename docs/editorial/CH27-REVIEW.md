## Principle-only self-test

- **Uncontrolled route percentage:** the Principle requires the same workload/configuration and repeated times. It also requires the accepted calls and forbidden combinations to be written down. A changed file set does not establish a speedup of the changed type, and Record need not preserve a required id. A single before/after percentage supplies neither the controlled measurement nor the contract evidence.
- **Brand and runtime allegation:** identify running versus checking. Compare the emitted implementations to see whether the erased brand added executed instructions. If a constructor/validator is also removed, the implementation and its rejections changed; byte identity from the annotation-only edit cannot justify that different change.
- **Faster emitter and forwarded caller:** the Principle explicitly denies that rejecting the same typo proves relationship preservation. An independently union-valued event and a payload for only one event need examination, as do the accepted forwarding calls. NoInfer cannot make an already-union event a singleton; the chapter supplies the analogous translator counterexample without teaching the event example again.
- **Two million instantiations:** counters describe work rather than price it in seconds. Ask for repeated elapsed cost on a defined workload and for the newly accepted mistakes before removing the check. The owner must name a replacement detector or the accepted risk. A larger counter with a faster measured check is not a contradiction; a smaller counter need not be a speedup either.

These are my applications, not independent-reader answers. The Principle is two paragraphs of requirements. The reader should be able to distinguish a measurement control from an error-preservation control without needing the story's command flags.
